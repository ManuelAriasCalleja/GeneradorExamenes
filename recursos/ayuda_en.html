Exam Generator

User manual

This manual explains how to use the program. The index on the left takes you to each section, and the box at the top searches for a word in the whole text, ignoring accents and capitals (Enter moves to the next occurrence).

Press F1 in any window of the program and the help opens at the section about that window. Dialogs also have a Help button that does the same.

Getting started

The program generates multiple-choice exams by picking questions at random from a question bank, with the number of questions you specify for each topic. When choosing them it follows the rules of the subject’s exams: it never puts two versions of the same question in the same exam, it can spread the correct answer across a), b), c) and d), and it can make each exam fit on one page per 10 questions.

It works for any subject: each question bank carries the name of its own subject, its topics (as many as it has) and its distributions of questions per topic.

It is also a tool for maintaining the bank: searching, correcting and adding questions, reviewing their wording, keeping the exams of each exam session and taking the questions to Moodle so that students can practise.

The bank file

The questions are stored in a database file (.db) that does not come with the program: either the teaching team gives it to you or you create it yourself. The first time, the program asks which bank to open or whether you want to create a new one; after that it always opens the last one that was opened. When opening or creating a bank, the dialog starts in the folder of the last one that was opened.

  • To switch to another bank: File → Open question bank…
  • To start an empty one: File → New question bank… When it is created, the program asks for the name of the subject and offers to import questions from a JSON file (see Importing and exporting the bank). Then the topics are created in Edit → Topics… (see Topics).

The status bar, at the bottom, shows which bank is open, how many topics and questions it has and how many of those questions are active. The window title includes the name of its subject.

The whole bank is in that single file, including the subject name, the distributions of questions per topic, the exam options and the exam session history. To make a backup or take it to another computer, just copy the file (with the program closed).

Several subjects

Each subject has its own bank, and each bank carries its own things: its questions, its exam session history and what you leave in the Generate exam tab (the list of exams, the instructions, the options, the scoring and the last distribution), as well as the folder where its exams are exported. So, when generating the exams of one subject, the questions from its own recorded exam sessions are avoided, and each subject has its own list of exams and its own folder. You switch from one to another with File → Open question bank…; if the exams in the window have been exported but not recorded, you are first asked whether to record them in the bank they belong to.

A bank that does not yet have its own options (a new one, or one from an earlier version of the program) takes, the first time, those in the window, except the exports folder, which is the bank's own folder (or the one that was in use, if it is the last bank opened). Check them before generating its first exams.

The main window

The window has two tabs:

  • Generate exam: on the left, the exam session details, the number of questions from each topic and the options; on the right, the generated exams and the buttons to print them, export them, record them in the history or take them on screen.
  • Question bank: the list of questions, with its filters, and the details of the selected question.

The menus hold everything else: File (opening and creating banks, importing and exporting, exam session history), Edit (topics, new question, style check) and Help.

The instructions, the list of exams, the options, the scoring and the last distribution of questions are saved in the bank, like the subject name, so each bank has its own and, when you open it again, they appear as you left them (see Several subjects). The exam session and the year, on the other hand, are set on start-up to those of the next exam session (see Exam session).

The first time

To avoid repeating questions from the last exam sessions, the program looks them up in its history, where the exams generated with it are saved. Exam sessions from before the program was used are not there, and their questions could come up again. Before generating the first exams, record the previous ones from their PDFs with File → Record previous exams… (see Recording previous exams). As long as none has been recorded, a warning is shown when generating.

An exam step by step

  1. In the Generate exam tab, check the exam session and the year: the program suggests the next exam session.
  2. Tick the exams you want in the list, for example “Nacional Original” and “Nacional Reserva”.
  3. Enter how many questions you want from each topic, or click one of the distribution buttons (for example, T1–T4) to apply a usual distribution.
  4. Click Generate exams. Check each exam on the right (switch from one to another in Exam) and read the warnings in the yellow box, if there are any.
  5. If you are not happy with a question, replace it with another by right-clicking it (see Replacing a question). If you are not happy with the whole set, click Generate exams again: different ones come out each time.
  6. Click Export PDF… to save the exams and Solutions PDF… to save the solutions.
  7. When they are final, click Record exam session…: they are saved in the history and their questions will be avoided in the following exam sessions.

Generating exams

Everything is done in the Generate exam tab. Fill in the panel on the left, from top to bottom, and click Generate exams. All the exams of the exam session are generated at once (one for each name ticked in the list) and appear on the right. If you generate again, they are replaced by new ones.

Exam session

  • Subject: the name printed in the exam header. It is the name of the open bank’s subject: if you change it here, it is saved in the bank (and appears in the window title).
  • Exam language: the language of the text that the program writes in the exams (the instructions it suggests, the scoring, “WITH SOLUTIONS”, the solutions sheet and the exam session months) and in Moodle. The questions appear as they are written. It is saved in the bank, like the subject: a bank for a subject taught in Spanish produces its exams in Spanish even if the program is in English, and a bank for a subject taught in English produces them in English even if the program is in Spanish (the interface language is chosen separately, see Settings). When you change it, the exam sessions in the list switch to the new language, and so do the instructions if they had not been changed. It also decides which style guidelines are checked.
  • Exam session: choose February, June or September (their names are in the exam language: Febrero, Junio and Septiembre in Spanish), or type another name. Together with the year it forms “June 2026”, which goes in the header, in the footer of each page and in the names of the exported files.
  • Year.
  • When the program starts, the exam session and the year are those of the next exam session according to the date: the first of February, June and September whose month has not yet arrived. From September to January, it is February; from February to May, June; and from June to August, September. If you are preparing another one, change them.
  • Instructions: the text of the instructions box below the header. The scoring is added below it. If an exam does not fit on its page, shortening the instructions helps.

List of exams

One exam is generated for each ticked name, in the order of the list. The footer of each page carries the name of the exam, the exam session and the year: “Nacional Original · June 2026: 1 / 2”.

  • Add (Alt+D): adds a new name, which you type in at that moment.
  • Remove (Alt+R): removes the selected name from the list (it asks for confirmation).
  • All (Alt+A) and None (Alt+N): tick or untick all the names.
  • Double-click a name to change it; drag it to change its position.

The shortcut letter of each button is underlined on it (on some desktops, only while Alt is held down).

The list is saved in the bank, so each subject has its own, and it is kept from one year to the next. There cannot be two ticked exams with the same name, nor one without a name.

Questions per topic

There is one box per topic with the number of questions you want from it. Next to it, in grey, “of N” shows how many different questions there are: the variants a, b, c… of a question count as one, because only one of them can appear in an exam (see Codes, variants and pseudo-duplicates). Voided and obsolete questions do not count, and neither do those flagged for review unless the option “Include questions flagged for review” is ticked.

Below are the buttons for the subject’s usual distributions, which are saved in the bank: each one sets the number of questions from each topic (hover the mouse over it to see how many). None sets all the topics to 0. For example, those of an eight-topic bank examined in two parts could be these:

T1–T4First part: 3, 2, 3 and 2 questions from topics 1 to 4 (10 in total).
T5–T8Second part: 2, 3, 2 and 3 questions from topics 5 to 8 (10 in total).
T1–T8Both parts together: 20 questions.
  • Save distribution… saves the current number of questions from each topic as a new distribution, under the name you give it (a name such as “T1–T4” is suggested): its button appears. If there is already one with that name, it asks whether to replace it.
  • Right-click a distribution to replace it with the current numbers of questions or to remove it.

The total is shown below. The program remembers the last distribution used in each bank; the first time, it suggests the first of its distributions. A new bank has none.

Scoring

There are four ways of scoring. In the first three, the exam is worth 10 points (each correct answer, 10 divided by the number of questions) and the points are worked out automatically:

ScoringWith 10 questionsWith 20 questions
Each wrong answer deducts 30% of the value of a correct one+1 and −0.30+0.50 and −0.15
Each wrong answer deducts 33.3%: just enough for random guessing to score 0 points on average (with four options, one guess in four is right, and that correct answer makes up for the other three wrong ones) +1 and −0.33+0.50 and −0.17
Wrong answers deduct nothing+1 and 0+0.50 and 0

With Custom, whoever sets the exam enters the points for each correct and each wrong answer in Correct and Wrong. Points have two decimal places, as they are printed. Unanswered questions neither add nor deduct anything.

The scoring is printed below the exam instructions and is used to mark the exam when you practise an exam.

Options

OptionWhat it does
Do not repeat questions between exams No question (nor any variant of it) appears in two exams of the same exam session. If there are not enough, a warning is shown and, from some exam onwards, some are repeated.
Avoid questions from the last N exam sessions Leaves until last the questions that appeared in the last N exam sessions recorded in the history, together with their variants and pseudo-duplicates. The exams being generated do not count as already used, even if they had been recorded before: when they are recorded again, they replace the old ones. Those from exam sessions before those N count as not used: with a number greater than the number of recorded exam sessions (for example, 99) all of them are avoided, and the first to come back are those used longest ago.
Also avoid those marked “old” Leaves until last the questions that already appeared in exams from before the history was kept (those marked “old” in the bank), though ahead of those from the recorded exam sessions.
Include questions flagged for review If unticked, questions flagged for review are not used.
Random order Shuffles the questions of the exam. If unticked, they are ordered by topic and number, as in the official exams.
Shuffle the options Changes the order of the options to spread the correct answer across a), b), c) and d) (see Distribution of the correct answer).
Fit on one page per 10 questions Compacts the layout until each exam fits on one page per 10 questions, and warns if it cannot (see One page per 10 questions). If unticked, exams use the normal layout and take as many pages as they need.
Seed If empty, different exams come out each time. With a number, the same ones come out again (see The seed).

How the questions are chosen

  • Voided or obsolete questions are never used.
  • Two variants of the same question (for example, T2-4a and T2-4b) never appear together in an exam, nor do two pseudo-duplicates, which are equivalent questions from different topics linked in the question editor.
  • From each topic, the questions that have never been used are chosen first; then, if “Also avoid those marked old” was ticked, those marked “old”; and finally those from the recorded exam sessions, from the oldest to the most recent. That way, if a question has to be repeated, it is the one that was used longest ago. When the program has to fall back on them, a warning is shown.
  • Exam sessions are ordered by year and, within the year, by month, if they are named after a month (February, June, September…).
  • Among the questions that are equally well placed, one is chosen at random.

Distribution of the correct answer

With Shuffle the options ticked, in each exam the correct answer falls on a), b), c) and d) the same number of times (with a difference of one at most) and, where possible, never three times in a row on the same letter. Questions with options that refer to the others (“All of the above”, “a and b”…) are not shuffled, because their meaning would change.

Without shuffling, the correct answer stays on the letter it has in the bank. If in any exam one letter comes up considerably more often than its share (5 out of 10, for example), a warning is shown.

Next to Large print you can see how many times each letter is correct in the exam being shown (“Correct: A 3 · B 3 · C 2 · D 2”). The solutions sheet also shows it.

The exam preview

The right-hand part of the tab shows the generated exams exactly as they will be printed.

  • Exam: which of the exams of the exam session is shown.
  • Show solutions: in the preview, puts the exam’s answer key at the top, marks the correct answer in green, shows the code of each question and puts its explanation and reference below it (see Printing and exporting). When exporting to HTML or LaTeX, it decides what is suggested for the “With solutions” box of the dialog.
  • Large print: the adapted version (see Large print).
  • The grey line below shows the seed, the level of the compact layout, if it has been used, and the recording date, if the exams have been loaded from the history. Its text can be selected and copied.
  • The yellow box gathers the warnings: topics without enough questions, repeated questions, a letter that is correct too many times, an exam that does not fit on its page… It is worth reading them before exporting.
  • Question and Replace with another, below the preview: replace a question of the exam being shown (see Replacing a question).

Replacing a question

If you are not happy with a question in an exam, there is no need to generate them all again: right-click it and choose “Replace question N with another from topic T”. You can also enter its number in Question, below the preview, and click Replace with another. The preview stays on the new question, and the status bar says which question has come in and which has gone out.

  • The new one is from the same topic and goes in the same place. If the options are shuffled, its correct answer stays on the same letter as that of the removed question, so neither the rest of the exam, nor the other exams, nor the distribution of the correct answer change.
  • It is chosen with the same rules as when generating: never a variant or a pseudo-duplicate of another question in the exam; if questions are not repeated between exams, none from the other exams; and first the ones that have never been used, then the “old” ones and finally those from the recorded exam sessions, from the oldest to the most recent.
  • If you replace it again, the questions already removed from that exam do not come back as long as there are others left.
  • If the new one is not among the desirable ones (for example, because it is already in another exam or was used in a recent exam session and there was no other left), the yellow box warns you. If no question can take its place, nothing is changed and a warning is shown.
  • Undo the change (or “Undo the last question change”, by right-clicking) undoes the changes, from the last to the first.

Questions can also be replaced in exams loaded from the history; the replacements are then chosen with the options currently set in the window. If the exams are then recorded again, they replace the ones that were there.

After replacing questions by hand, the seed no longer reproduces the exams (the grey line says so). To keep them, record them.

One page per 10 questions

With the Fit on one page per 10 questions option ticked (it is, unless you untick it), each exam must fit on one page per 10 questions: a 10-question exam, on a single sheet. If it does not fit with the normal layout, the program compacts it in levels: it puts the options in two columns (a c / b d) when they take up fewer lines that way, reduces the spacing between questions and, finally, reduces the font size (down to 9 points). The level used appears in the grey line (“Compact layout (level 2 of 4)”) and is the same for all the exams of the exam session, in the preview, when printing and in the three exports.

If it still does not fit, a warning is shown: shorten the instructions or remove a question (those with an image or a long question text take up the most space).

If the subject has no such limit, untick the option: the exams will use the normal layout and take as many pages as they need, and the grey line will say “No page limit”. Like the other options, it is saved in the bank.

Large print

The Large print box produces the adapted version for visually impaired students, the opposite of the compact layout: 16-point font (also in the header and the instructions), question texts in bold without italics, one option per line, more spacing between questions and larger images, with no page limit.

It applies to the preview, printing and all exports. The files have “_letra_grande” in their name (2026_Junio_letra_grande_Nacional_Original.pdf), so as not to overwrite the normal ones. They are the same exams, with the same questions in the same order: just export the normal ones, tick the box and export again.

The seed

Each time exams are generated, a number called the seed is used; it appears in the grey line. If you enter that number in Seed and generate again with the same settings, exactly the same exams come out, provided that neither the bank nor the history has changed.

While a seed is entered, the same exams come out every time: the field is shown in yellow and the grey line says “fixed”. To get different ones again, clear it (with the cross in the field).

If questions have been replaced by hand, the seed no longer reproduces the exams. To recover the exams of a past exam session, the history is a better option: it keeps them exactly as they were set, even if their questions are corrected later.

Printing and exporting

Once the exams have been generated, the buttons below the preview print them or save them to files:

The solutions (Solutions PDF…, and HTML or LaTeX with the “With solutions” box ticked) start with the solutions sheet: the structure of the exam session (which questions from each topic each exam has) and, for each exam, its answer key (“1 C”, “2 A”…, in rows of 10), how many times each letter is correct and the code, answer and reference of each question. Then come the exams with the correct answer in green and, below each question, its explanation (why it is the correct one) and its reference to the text, if the bank has them.

To print the solutions, export them with Solutions PDF… and print the PDF.

Folder and file names

When exporting, a dialog opens:

  • Folder: where the files are saved. It is remembered from one time to the next in each bank (each subject has its own); Choose… lets you pick another one. If it does not exist, it is created.
  • The table has one row per exam: the ticked ones are exported, each to its own file. Click a file name to change it.
  • If there is more than one exam, the last row, “All the exams in one file”, also saves them all together in a single file, each starting on a new page.
  • When exporting to HTML or LaTeX, the With solutions box decides whether the solutions are included. It is suggested ticked if “Show solutions” is ticked. When it is ticked, the suggested names include “_soluciones” (2026_Junio_soluciones_Nacional_Original.html), like those of Solutions PDF…, so as not to overwrite the others.

If any of the files already exists, you are asked for permission to overwrite it. When the export is finished, the status bar says where the files have been saved and, on the right, the Open the folder button opens it (it stays there until other exams are generated).

HTML and LaTeX exports save the images of the questions in a folder next to the file, <name>_imagenes. If you move the file, you must take that folder with it.

LaTeX

Export LaTeX… saves .tex files to be compiled with pdflatex. With the “With solutions” box of the dialog ticked, they also include the solutions sheet and the exams with the solution marked, the explanation and the reference. They must be compiled twice for the “page / total” in the footer to come out right:

pdflatex examen.tex
pdflatex examen.tex

Practising an exam

Practise this exam… opens the exam being shown so that you can take it on screen, as a student would, and have it marked. It is useful, for example, for checking an exam before approving it.

  1. Choose the duration (from 5 to 300 minutes; it is remembered from one time to the next) and click Start. Until then, no answers can be given.
  2. To answer, click the letter or the text of an option. Leave blank clears the answer to that question.
  3. The clock counts down and turns red in the last 5 minutes. If time runs out, the exam is marked automatically.
  4. Click Finish and mark when you have finished.

When the exam is marked, each question shows whether it is right, wrong (and which answer was correct) or blank, with its code, the reference to the textbook and the explanation, if it has one. The correct answer is shown in green and the wrong answer is struck through in red. The score is calculated with the scoring of the main window.

The exam session history

The history keeps, inside the bank, the exams set in each exam session. It serves two purposes: preventing the questions from the last exam sessions from being repeated in the following ones, and being able to recover an exam exactly as it was set. Each bank has its own: the exam sessions of one subject do not count in another (see Several subjects).

Recording an exam session

Record exam session…, below the exam preview, saves the generated exams in the history: a copy of their questions exactly as they were set, the order of the options and the exam session details (subject, instructions and scoring). The name of the exam session must have been entered.

If exams with the same name, exam session and year had already been recorded, they are replaced (confirmation is asked first). So, if you generate the exams of an exam session again after recording it, just record it again.

From then on, the option “Avoid questions from the last N exam sessions” takes those exams into account, and the details of each question, in the Question bank tab, show which exams it has appeared in.

Record only the final exams: the recorded ones count as already used when generating the exams of the following exam sessions.

So that you do not forget, while the exams in the window have been exported (or printed) but not recorded, the Record exam session… button is shown in yellow and the grey line says “Exported but not recorded”. If they are then about to be lost (when generating others, loading from the history, opening another bank or quitting the program), you are asked first: Record them…, Do not record them or Cancel.

Recording previous exams

The exams of exam sessions held outside the program (those from before it was used) are recorded with File → Record previous exams…. That way their questions are avoided when generating the following ones, just like those of the generated exam sessions.

  1. Click Add PDF… and choose the PDFs of the exam session’s exams (several at once). If an exam is only available in Word, open it, select all its text, copy it and click Paste text….
  2. The program splits each exam into questions, numbered “1.-”, “2.-”…, with their options “a)”…“d)”, and recognises each one in the bank by its similarity. It also works out the order in which its options appeared.
  3. The exam session, the year and the name of each exam are suggested from the file name (2026_02_05_ae_original_ex_fi.pdf is “América Este Original” from February 2026), using the names in the list of exams. Check them: double-click a name to change it.
  4. Review the questions of each exam (they are shown when you select it in the list). The uncertain ones, which are not very similar to the recognised question or are almost as similar to another one, are shown in yellow. Hovering the mouse over the code shows the text of that question in the bank and, over “In the exam”, the text that was read. To correct one, double-click its code and enter the right one (T1-7a).
  5. Click Record. The exams are saved in the history like the generated ones, with the usual scoring (10 points, and each wrong answer deducts 30%). If exams with the same name had already been recorded in that exam session, they are replaced.

The questions are recorded as they are now in the bank, not as the text of the PDF: when one of these exams is loaded from the history, it comes with the current questions. To read PDFs, the program needs the Qt PDF library; if Add PDF… is disabled, copy and paste the text.

Loading or deleting exam sessions

File → Exam session history… shows the recorded exam sessions (for example, “June 2026”) with their exams, the number of questions in each one and when it was recorded.

  • Load (or double-click an exam): takes the selected exam session, or a single exam, to the Generate exam tab, so that you can view, export, print or practise it exactly as it was set, even if its questions have been corrected since. The exam session details are copied to the window (subject, exam session, year, instructions and scoring; if the scoring does not match the one in the window, the recorded one is set, as Custom). The grey line says “Recorded on …”.
  • Delete from history…: deletes the selected exam session or exam, after asking for confirmation. Its questions no longer count as already used, and it cannot be loaded again.

After loading a past exam session, check the exam session and the year before generating new exams.

The question bank

The Question bank tab shows all the questions of the bank in a table. When you select one, its details are shown on the right: the question text, the options, the correct answer with the reference to the textbook, the explanation, the question it is linked to, the notes and which recorded exams it has appeared in.

Searching and filtering

  • Topic: only the questions of one topic.
  • Status: all, active, voided, obsolete, flagged for review or with an image.
  • The search box finds the questions that contain a piece of text in the question text, the options or the notes, ignoring capitals and accents (“resume” finds “Résumé”). If you type a code (T1-22b), it finds that question.

To the right of the filters you can see how many questions meet the conditions. Click a column heading to sort by that column. Hovering the mouse over a question text also shows its options. Voided and obsolete questions are shown struck through and in grey.

Table columns: Topic; Code (number and variant, with “(old)” if it already appeared in exams from before the history was kept); Status (active, voided or obsolete, with “review” and “image” where applicable); Question text; and Ans., the letter of the correct answer.

Codes, variants and pseudo-duplicates

Each question has a code with its topic, its number and, if it has one, its variant letter: T1-22b is variant b of question 22 of topic 1.

  • Variants: questions of the same topic with the same number (T2-4a, T2-4b…) are versions of the same question: different data, the question the other way round or another aspect of the same concept. Two of them never appear in the same exam, and when counting the questions available in a topic they count as one.
  • Pseudo-duplicates: two questions from different topics that ask the same thing are linked with the “Pseudo-duplicate of” field of the editor (for example, T3-5 with T1-7). They never appear together either.

Status and marks of a question

Status or markMeaning
ActiveIt can appear in exams.
VoidedIt is never used, but it is kept in the bank.
ObsoleteIt is never used: it no longer matches the syllabus.
oldIt already appeared in exams from before those recorded in the history. It can be left until last with the option “Also avoid those marked old”.
Flagged for reviewIt needs improving. It appears in exams unless “Include questions flagged for review” is unticked.

Creating, editing and deleting questions

  • New… (or Edit → New question…, Ctrl+N): opens the editor with an empty question, in the topic selected in the filter (or in the first one) and with the first free number. To write several in a row, Save and new saves the question and opens another one in the same topic.
  • Edit… (or double-click the question): opens the selected question in the editor. To go through several, Save and next saves the question and opens the next one in the table, with its current filter and sort order.
  • Duplicate as variant…: copies the selected question as its next variant, with the first free letter (if the question has no letter, it counts as “a”), so that you can write another version of it. The copy does not have the “old” mark.
  • Delete: permanently deletes the question from the bank, after asking for confirmation.
If you only want a question to stop appearing in exams, do not delete it: edit it and set it to voided. That way it is kept, with its history, and can be recovered.

The question editor

The editor opens when a question is created, edited or duplicated. The details are on the left; on the right there is a preview of the question, which is updated as you type, with the style warnings and the similar questions below it.

  • Identification: the topic, the number and the variant (a letter, or nothing if there are no variants); the status (active, voided or obsolete); the marks “Already used in exams (old)” and “Flag for review”; and “Pseudo-duplicate of”, the code of the equivalent question from another topic (for example, T1-7). See Codes, variants and pseudo-duplicates.
  • Question text and answers: the question text (see Question text format) and the four options. The selected round button indicates which one is correct. All four options are required.
  • Image: optional; it is shown below the question text. Load… accepts PNG, JPG, BMP and GIF, and saves the image in the bank; Remove deletes it. In the exams, if the image is narrow enough for each option to fit on one line to its left, the options go one below the other with the image to their right, aligned at the top; otherwise, the image goes below the question text and the options below it. This is only done if the question does not take up more space that way (a very short image with options that fit on one row stays below), and never with large print.
  • Reference and notes: the reference to the textbook, which goes in the solutions; the explanation of the answer, which is shown when a practice exam is marked and in Moodle; and the internal notes, which are only shown in the bank.

When you click Save, the program checks that there is a topic, a question text and all four options. If the question does not follow some of the style guidelines, it lists them and asks whether to save it anyway or continue editing. If it is a new question, with a number that does not exist yet, and it is very similar to others in the bank, it shows them before saving it (see Similar questions).

When you create a new question and change its topic, the suggested number becomes the first free one in the new topic.

If you click Cancel (or press Esc, or close the window) with unsaved changes, you are asked before they are discarded.

Question text format

The question text is plain text, in one or more paragraphs. It also accepts code and tables:

  • Code: between two lines containing only three backticks (```). It is printed in a grey box, so that it stands out from the text, in a fixed-width font and keeping the spaces; lines that do not fit in the width of the page are wrapped. The same in the preview, the exports and Moodle.
  • Tables: each row on one line, with the cells separated by bars: | cell | cell |.

For example:

Text of the question, in one or more paragraphs:
```java numerado
int total = 0;
for (int i = 1; i <= 3; i++)
    total += i;
```
| Column 1 | Column 2 |
| data     | data     |

The line that opens the code can say its language, and then it is highlighted (keywords in bold blue, comments in grey italics, strings in maroon: it can also be told apart when printed in black and white), and numerado (Spanish for “numbered”), so that it has line numbers on the left: ```java, ```xml numerado, ``` numerado. The languages are:

WrittenFor
xmlXML, and also XML Schema, XSLT, WSDL or SOAP (xsd, xsl, xslt, wsdl and soap are accepted).
dtdA DTD, or an XML document with its internal DTD.
idlCORBA IDL.
html, json, yaml (or yml), java, c, python, sqlThose languages.
texto, or nothingNot highlighted.

After ``` only the language and numerado may go. A language that is not in the list, an extra word or a code block that is not closed give a style warning (and when checking a JSON file). The preview shows how it will look.

Style guidelines

As you type, the bank’s writing guidelines that the question does not follow appear in yellow below the preview. They are warnings, not errors: there may be justified exceptions, and the question can be saved anyway. The guidelines come from a style guide for questions written in Spanish, so the forms they check for are quoted here in Spanish:

  • Question text: it must begin with a capital letter and end with a colon, or with “?:” if it is a question, with both its opening and closing question marks (“¿” and “?”); it should not exceed about 180 characters; negations go in capitals (“NO”, “FALSO”); literals go in typographic quotation marks (“…”) in the text and in straight quotation marks (") inside code.
  • Options: they begin with a capital letter and end with a full stop; they must not be repeated; options that refer to the others (“Todas las anteriores”, “a y b”…) are best avoided, because they prevent shuffling; and the correct one must not be much longer than the others, because that would give it away.
  • Reference: it must be present, end with a full stop and include the page number, in the format required by its topic (see Topics): “Véase la página N (sección X.Y) del libro de teoría.” or “Pág. N libro (subsección X.Y.Z).”.

These are the guidelines of a style guide written for Spanish. In a bank whose exams are in another language (see Exam session) only those that do not depend on the language are checked: the length and the initial capital of the question text, the quotation marks in code, identical options, options that refer to the others (also in English: “All of the above”…), a correct option that is much longer than the rest, and the presence of a reference.

To check the whole bank at once, see Checking the bank’s style.

Similar questions

Below the preview, in blue, the editor shows the questions in the bank that are most similar to the one being written, with their percentage of similarity. Only questions with other numbers count: variants of the same question do not. The similarity compares fragments of words in the question text and the options.

When you save a new question with a number that does not exist yet, if it is very similar to others, a dialog opens with them: the list on the left, with the percentage of similarity; on the right, the details of the selected one. If it is the same idea, they should never appear together in an exam:

  • Save as a variant of… (if the selected one is from the same topic): the question takes the number of the selected one and its next free letter.
  • Link to… (pseudo-duplicate) (if it is from another topic): its code is entered in “Pseudo-duplicate of”.
  • Save as a new question: it is saved as it is.
  • Continue editing: goes back to the editor without saving.

Topics

Edit → Topics… shows the topics of the bank: their number, title and author, the format of the textbook reference in their questions and how many questions they have. Each subject has as many topics as it needs.

  • Double-click a cell to change the number, the title or the author.
  • Textbook reference: the format that the style check requires for the reference in the topic’s questions, which depends on its author: one of the two Spanish forms “Véase la página N (sección X.Y) del libro de teoría.” and “Pág. N libro (subsección X.Y.Z).”, or “Any” (not checked).
  • Add topic creates one with the number following the last one.
  • Delete topic removes it. If it has questions, it warns you: they would be deleted with it.

The changes are not applied until you click Save, and then they are all applied at once. Topic numbers must be positive and different from each other. If the number of a topic is changed, the bank’s distributions follow it; if a topic is deleted, they lose it.

Checking the bank’s style

Edit → Check the bank’s style… checks the style guidelines in all the questions of the bank and lists those that do not follow them, with their warnings.

  • Show: all warnings, or only those about the question text, the options or the reference.
  • Include voided and obsolete questions: by default only active ones are checked.
  • Edit the question… (or double-click): opens the question in the editor so that you can correct it. When you return, the list is updated. With Save and next with warnings, the editor saves the question and opens the next one in the list, without having to go back to it.
  • Save the report…: saves the list in a text file (by default, next to the bank). It contains only the codes of the questions and the warnings, not their text.

Importing and exporting the bank

As well as in the database, the bank can be saved in a JSON file, which is plain text: it is useful for moving the questions from one bank to another, for creating the bank from the teaching team’s questions document and for adding many questions at once, written with a text editor (see JSON format).

Import and export

  • File → Import questions (JSON)… asks how to import:
    • Add/update: the questions in the JSON with the same topic, number and variant as one in the bank replace it; the other questions in the bank are kept.
    • Replace all: first deletes all the topics and questions in the bank. Before deleting them, it saves a backup.
    First, the JSON is checked (see Checking a JSON file): if it has errors, it is not imported; if it only has warnings, it can be imported anyway. If the bank does not yet have a subject name or an exam language, it takes those of the JSON; if it does, it keeps them. Topics in the JSON that do not state their title, their author or the format of their reference (those from the questions document do not state the format) keep the ones that the topic with that number already had: to add questions to a topic that is already in the bank, just give its number and the questions.
  • File → Export questions (JSON)… saves the whole bank in a JSON file.

JSON format

A JSON file of questions can be written with any text editor (Notepad, VS Code…). File → Save an example JSON… saves one with some made-up questions that use everything that can be included: the easiest way is to start from it. Its first field, $schema, is the address of the format’s schema: with it, editors that understand JSON schemas, such as VS Code, flag errors and suggest fields as you type. The JSON files exported by the program include it too.

It has this form (the questions of each topic go in its preguntas list, separated by commas):

{
  "asignatura": "Name of the subject",
  "idioma": "en",
  "temas": [
    {
      "numero": 1,
      "titulo": "Title of the topic",
      "preguntas": [
        {
          "numero": 1,
          "enunciado": "Text of the question:",
          "opciones": ["First.", "Second.", "Third.", "Fourth."],
          "correcta": "B",
          "referencia": "See page 12 of the textbook."
        }
      ]
    }
  ]
}

What the whole JSON and each topic can contain (required fields in bold):

FieldWhat it is
temasThe list of topics, with their questions.
asignaturaThe name of the subject. It is only used if the bank does not have one yet.
idiomaThe exam language: "es" (Spanish) or "en" (English). It is only used if the bank does not specify one yet.
$schema, origenThe address of the schema, and where the questions come from (for information only).
numero (of the topic)The topic number. If the topic is already in the bank, the questions are added to it.
titulo, autorThe title of the topic and its author in the textbook. If they are not given, a topic that is already in the bank keeps its own.
formato_referenciaThe format of the reference required in its questions (see Topics): "vease", "pag" or "" (any).
preguntasThe list of the topic’s questions.

And each question:

FieldWhat it is
numeroThe number of the question within its topic, without quotes. Questions with the same number are variants (see Codes, variants and pseudo-duplicates). If the bank already has one with the same topic, number and variant, it is replaced.
varianteThe variant letter: "a", "b"… or "" if there is none.
enunciadoThe text of the question, in the question text format (code blocks and tables). Line breaks are written \n.
opcionesThe four options, a), b), c) and d), without the letter: a list of four texts.
correctaThe letter of the correct answer: "A", "B", "C" or "D".
referenciaThe reference to the textbook.
explicacionWhy the correct answer is correct: it is shown in the question’s details and goes to Moodle.
notasInternal notes, which do not appear in the exams.
estado"activa" (active; the default if omitted), "anulada" (voided) or "obsoleta" (obsolete) (see Status and marks of a question).
old, revisarAlready used in exams; flagged for review: true or false, without quotes.
pseudo_conAnother, equivalent question from another topic, with which it will never appear: its topic and number, such as "T1-7".
imagenA PNG or JPG image encoded in base64. It is easier to add it later from the question editor.
codigo, etiqueta_originalFor information only: they are written by the program and by the questions document tool; when importing, numero and variante are what count.

To write questions, or to ask an assistant such as Claude for them, there is a guide (in Spanish) with the format, how code is written and the rules that are checked: Redactar preguntas para el generador de exámenes. For an assistant, it is enough to give it the address.

The things most often forgotten when writing a JSON file by hand: texts go in straight double quotes (", not “ ”, which appear when copying from a word processor); inside a text, a quotation mark is written \" and a backslash \\; true, false, null and numbers go without quotes; the items of a list and the fields of an object are separated by commas, but with no comma after the last one; and comments are not allowed.

Checking a JSON file

File → Check a JSON file… reads a JSON file of questions, without importing it, and lists all its problems at once: each with its line, the question it is in (“topic 3, question 12b”) and what is wrong.

  • Errors: the JSON is badly written (a comma too many or too few, unclosed quotes…), a required field is missing or a value is not valid (a correct answer “E”, three options, a status that does not exist, a repeated question…). A file with errors cannot be imported.
  • Warnings: a field that is not part of the format, which is ignored (if it looks like one that is, because of a typo, it says so: ‘Did you mean “enunciado”?’); a pseudo-duplicate of a question that is neither in the JSON nor in the bank; identical options; a topic without a title; a code block in a language that is not highlighted, with extra words after the ``` or not closed. They do not prevent importing.

With the JSON open in a text editor, correct what it says, save it and click Check again. Open the file opens it with the program that the system associates with it, and Copy the report copies the list as text, for example to send it by email.

The same is done when importing: if the JSON has any problem, this list is shown first; with errors it is not imported, and with warnings you can click Import anyway.

It can also be checked without opening the program, from the command line (on Windows, from the console): GeneradorExamenes --comprobar preguntas.json. It writes the problems the way compilers do (preguntas.json:12:5: error: topic 3, question 12b: …), which many editors understand, and exits with 1 if there are errors, so that it can be used in a script.

The JSON linked to the bank

The JSON file from which the whole bank is imported becomes linked to it as its text copy. When the database and that JSON no longer match (for example, after correcting a question in the program), the status bar shows a warning. Hovering the mouse over the warning shows how they differ; clicking it, or using File → Update the bank’s JSON…, overwrites the JSON with the contents of the database. The first time, if no JSON is linked, it asks which one it is.

With File → Keep the bank’s JSON up to date ticked, the program rewrites the JSON by itself after each change to the bank. It never touches a JSON that no longer matches the database (for example, one freshly generated from the questions document and not yet imported): in that case it only shows a warning.

Backups

Before “Replace all”, the program saves a copy of the database in the copias folder next to it, with the date and time in its name (copias/preguntas_2026-10-22_153045.db), and when it has finished it says where it has saved it. If the import fails, the database does not change and the copy is deleted.

To go back, open the copy with File → Open question bank… or, with the program closed, copy it over the bank.

From the questions document

When the teaching team publishes a new version of the Word document of questions, the person who maintains the bank converts it to JSON with the tool herramientas/importar_docx.py, which comes with the program’s source code, and imports it with File → Import questions (JSON)…. The labels in the document are interpreted as follows:

LabelIn the bank

ANULADA, OBSOLETAVoided or obsolete: never used.
MEJORAR, REFINAR, DEFINIR …Flagged for review.
PSEUDORREPETIDA … TEMA1 preg 7Linked as a pseudo-duplicate of T1-7.

Exporting to Moodle

File → Export to Moodle (XML)… saves the bank’s questions as a quiz in “Moodle XML” format, so that students can practise in the online course.

  • Active questions are included; voided and obsolete ones are not. Those flagged for review can be excluded.
  • One category per topic, inside one with the name of the subject (“Subject/Topic 1: …”).
  • Each question is multiple choice with a single correct answer. The reference to the textbook and the explanation go as feedback, and the images go inside the file itself.
  • If the option is ticked, wrong answers deduct 30% of the question’s value, as in the exam.
  • Moodle shuffles the options, except in questions with options such as “All of the above”.
  • What the program writes (the topic names, “Correct answer.”) is in the bank’s exam language (see Exam session).

The dialog suggests the file (the subject name without accents or spaces followed by _moodle.xml, for example Historia_del_arte_moodle.xml, in the exports folder) and says how many questions from how many topics will be exported.

In Moodle, the file is imported from Question bank → Import, choosing the “Moodle XML” format.

Settings

The program saves in a settings file the path of the last bank opened, the duration of practice exams, the window size and the interface language. What depends on the subject goes with each bank (see Several subjects): the subject name, the exam language, the distributions of questions per topic, the instructions, the list of exams, the options, the scoring and the exports folder; the settings file only keeps a copy of those of the last bank opened. The file is located at:

  • Linux: ~/.config/UNED/GeneradorExamenes.conf
  • Windows: %APPDATA%\UNED\GeneradorExamenes.ini

Help → About… shows where it is, together with the open bank and the version of the program. To go back to the initial settings, close the program and delete that file; the banks are not touched.

Up to version 1.0, the program was called GeneradorExamenesFI and its settings were in ~/.config/UNED-FI/GeneradorExamenesFI.conf (Linux) or %APPDATA%\UNED-FI\GeneradorExamenesFI.ini (Windows). The first time a later version is opened, they are copied from there; the old file is not touched.

On Windows, to move to a new version of the program, delete its folder and unzip the new one: the settings are kept.

From the command line you can specify the bank to open: GeneradorExamenes path/to/bank.db. If it does not exist, it is created. With --comprobar, JSON files of questions are checked without opening the program (see Checking a JSON file).

Language

Edit → Language chooses the interface language (menus, dialogs, warnings and this help): Español (Spanish) or English, or System default, which is used if none is chosen (if the system language is neither of the two, Spanish is used). It is saved in the settings, so each user has their own, and it takes effect the next time the program is opened: the message shown when you change it lets you restart it straight away.

It does not change the exam language, which goes with each bank (see Exam session).

Common problems

On start-up, it says that the question bank cannot be found

The file of the last bank has been moved or renamed, or it is on a disk that is not connected. Click Open bank… and find it (the dialog starts in the folder where it was or, if that no longer exists, in the nearest one that still exists); from then on the program will open it from its new location.

“There is no exam session recorded in the history”

While the history is empty, the questions from previous exam sessions are not avoided. If those sessions were held outside the program, record them from their PDFs (see Recording previous exams); if they were generated with it, record them with Record exam session…, or untick the option “Avoid questions from the last N exam sessions”.

“N questions were requested but only M different ones are available”

The topic does not have enough different active questions (variants count as one). Ask for fewer questions from that topic or, if there are some, tick “Include questions flagged for review”.

“There are not enough questions to avoid repeats between exams”

Across all the ticked exams, more questions are requested from a topic than it has. Generate fewer exams or untick “Do not repeat questions between exams”.

“There are not enough questions left that were not used in the last recorded exam sessions”

The program has had to use questions that appeared in the last recorded exam sessions, or that are marked “old”. It is only a warning: the ones used longest ago are chosen. If you prefer to avoid them, reduce the number of exam sessions that are avoided or ask for fewer questions from that topic.

“The correct answer is b) in 5 of 10 questions”

Without shuffling the options, the correct answer stays where it is in the bank and may fall on the same letter many times. Tick “Shuffle the options” and generate again.

“At least one exam does not fit on one page, even with the most compact layout”

Shorten the instructions or replace a long question or one with an image (by generating again or with another distribution). If the subject’s exams have no page limit, untick “Fit on one page per 10 questions” in the options. See One page per 10 questions.

I want to get back the exams from another day

If they were recorded, load them from the history. If not, and you noted down the seed, enter it in Seed and generate with the same settings (see The seed).

A question has an error and must not be used again

Correct it in the editor or, if it cannot be fixed, set it to voided. The exams already recorded in the history do not change: they keep the question exactly as it was set.

I have replaced the bank by mistake

Open the backup that was saved in the copias folder (see Backups).

Some dialog buttons are in English with the Spanish interface

This only happens with the interface in Spanish: the Spanish translations of Qt, the library the program is built with, are missing. It does not affect how the program works. (If the whole program is in English and you want it in Spanish, choose Español in Edit → Language: see Language.)
